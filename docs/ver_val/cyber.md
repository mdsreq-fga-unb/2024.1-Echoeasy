## 1. Introdução
Este documento trata da verificação e validação do PBB (Product Backlog Building) apresentado no estudo de caso "HealthNet" e da USM (User Story Mapping) apresentado no estudo de caso "ComunEventos" , realizado pelo grupo CyberHunterz e que pode ser acessado clicando [aqui](https://mdsreq-fga-unb.github.io/2024.1-ObjeX/healthnet-pbb/). A técnica de checklist foi utilizada para conduzir a atividade e abaixo pode-se visualizar as checklists de verificação e validação.

## 4. USM (User Story Mapping)
A seguir, apresentam-se as tabelas de verificação e validação relacionadas ao processo de User Story Maping (USM). Essas tabelas incluem as perguntaras que serão avaliadas, uma seção para confirmação (check) indicando se cada item está em conformidade, e um campo de observações destinado ao registro de eventuais apontamentos caso algum item não atenda aos critérios estabelecidos.

### Verificação USM

| Pergunta                                                                                                     | OK? |                         Observação                         |
| ------------------------------------------------------------------------------------------------------------ | --- | :--------------------------------------------------------: |
| As Personas estão devidamente identificadas?                                                                 | ✅  |                                                            |
| O USM está no devido padrão? (objetivos, jornada do usuário, tarefa de usuário)                              | ✅  |                                                            |
| Há separação das tarefas em iterações?                                                                       | ✅  |                                                            |
| O USM está seguindo um padrão linguístico? (verbos no infinitivo)                                            | ❌  | Tarefas do Patrocionador e Voluntários não seguem o padrão |
| Existe uma sequência lógica nas atividades?                                                                  | ✅  |                                                            |
| Nos cards de título de tarefa de usuário exitem as USs?                                                      | ✅  |                                                            |
| As histórias de usuários estão devidamente escritas? (eu como <cargo>, quero <ação> para <valor de negócio>) | ✅  |                                                            |

### Validação USM

| Pergunta                                                                                                                      | OK? | Observação |
| ----------------------------------------------------------------------------------------------------------------------------- | --- | :--------: |
| Os objetivos do usuário e do negócio estão alinhados?                                                                         | ✅  |            |
| Os objetivos abrangem o que o usuário deseja alcançar?                                                                        | ✅  |            |
| A jornada do usuário abrange o que o usuário faz no produto?                                                                  | ✅  |            |
| Os usuários seguem os passos descritos na jornada do usuário?                                                                 | ✅  |            |
| Os objetivos, a jornada e as tarefas de usuário estão claros e compreensíveis para pessoas fora da equipe de desenvolvimento. | ✅  |            |
| A partir do USM as histórias de usuário podem ser criadas?                                                                    | ✅  |            |
| As história de usuário estão relacionadas ao seu título?                                                                      | ✅  |            |
